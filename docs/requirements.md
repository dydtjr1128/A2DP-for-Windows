# 요구사항과 완료 기준

## 제품 방향

Windows PC를 Bluetooth Classic A2DP Source로 동작시켜, 기존 헤드폰(Sink)에 PCM을 인코딩한 오디오를 보냅니다. 사용자는 장치를 선택하고 사용 가능한 코덱·품질을 설정하며 실제 협상 결과와 실패 이유를 확인합니다.

첫 대상은 **Windows 11 x64, 어댑터 한 모델, 헤드폰 한 모델**입니다. 정확한 OS 빌드·장비 모델은 M1 시험 계획을 시작할 때 기록합니다. Windows 10, ARM64, 모든 Bluetooth 어댑터의 지원은 약속하지 않습니다.

## 사용자 흐름

1. 개발자가 선정 장비와 기본 Windows 드라이버 재생을 확인한다.
2. 전용 시험 환경에서 대상 장치에만 개발 드라이버를 적용한다.
3. 사용자가 연결된 장치를 선택하고 지원 가능한 코덱 후보를 확인한다.
4. 서비스가 양쪽 능력과 실제 탑재 인코더를 확인하고 스트림을 구성한다.
5. 사용자에게 요청값·실제값·fallback 이유를 표시한다.
6. 연결 단절·절전·프로세스 종료에서 음원과 핸들을 정리하고 허용된 경우만 재연결한다.
7. 사용 중단 또는 제거 시 원래 장치 드라이버와 재생 기능을 복구한다.

2번 이후는 아직 구현되지 않았습니다. 현재 저장소를 빌드한다고 Bluetooth 드라이버가 설치되거나 코덱이 활성화되지 않습니다.

## 기능 요구사항

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-01 | 장치와 실제 지원 능력 조회 | M1 | 페어링 목록·연결·A2DP Sink 능력을 구분하고 조회 실패를 미지원과 구분 |
| FR-02 | SBC 전송 | M1/M2 | 선정 장비에서 자체 경로로 시험 신호와 Windows 앱 소리가 재생됨을 각각 증명 |
| FR-03 | 코덱 후보 선택 | M0/M3 | 선호 순서, 로컬 구현, 원격 능력의 교집합만 선택; 허용하지 않은 fallback 거부 |
| FR-04 | 코덱별 상세 협상 | M2/M3 | 샘플레이트·채널·비트레이트 등 공통 형식만 제안하고 remote accept 전에는 활성으로 표시하지 않음 |
| FR-05 | 장치별 설정 | M3 | 장치별 희망 설정 저장, 스키마 검증, 임시 원격 오류로 기존 설정을 덮어쓰지 않음 |
| FR-06 | 실제 상태·진단 표시 | M2 | 선택 코덱, 활성 코덱, sample rate, queue/underrun/drop, 오류 이유를 구분 |
| FR-07 | 재연결·절전 복귀 | M2/M4 | 오래된 완료 통지가 새 세션을 바꾸지 않고 제한된 재시도로 복구하거나 이유를 표시 |
| FR-08 | 정상 제거·복구 | M1/M4 | 대상 장치의 원래 드라이버 상태를 기록·복원하고 OS 기본 재생을 재검증 |
| FR-09 | LDAC·aptX·aptX HD | M3 | 코덱별 권리 검토, golden vector와 실기 재생을 개별 통과 |
| FR-10 | AAC·aptX Low Latency | 후속 조건부 | 구현·특허·배포 조건과 실제 peer 동작을 확인한 뒤 별도 승인된 기능 범위로 편입 |
| FR-11 | 설정 UI | 설계 M0, 구현 M3 | [UI 계약](ui-design.md)과 UX-01~12 만족, 요청값·실제값·저장/적용 결과·접근성 검증 |

M0의 후보 선택 테스트는 FR-03의 순수 정책 부분만 검증합니다. FR-01/04 또는 실기 재생을 대신하지 않습니다.

## 비기능 요구사항

| ID | 원칙 | 초기 측정·완료 조건 |
| --- | --- | --- |
| NFR-01 | 메모리·시간 상한 | PCM/packet queue 용량 고정; hot path 무제한 할당·무제한 대기 없음 |
| NFR-02 | 커널 실패 격리 | codec FFI 우선 user mode, 커널 요청 취소·해제의 단일 소유권; Driver Verifier 결과 기록 |
| NFR-03 | 재현성 | OS·WDK·Rust·드라이버·codec revision, 장비·펌웨어를 함께 기록 |
| NFR-04 | 개인정보 최소화 | 원시 오디오 미저장, export 로그의 장치 주소·사용자 경로 제거, crash dump는 비공개 처리 |
| NFR-05 | 호환성과 복구 | 설치 전/후/제거 후 baseline 비교, 다른 Bluetooth 장치의 기능 보존 |
| NFR-06 | 지연·음질 정직성 | queue 지연과 end-to-end 지연 구분; 실측 전 저지연·무손실 주장 금지 |
| NFR-07 | 유한 재시도 | 오류 분류, 최대 시도·전체 deadline·사용자 취소 정의 |
| NFR-08 | 최소 권한 | 일반 UI는 비관리자; 설치 단계만 상승; 서비스·드라이버 접근 ACL 명시 |

성능의 숫자 목표는 [검증 계획](validation.md)의 **시험 목표값**입니다. 제품 보장값이나 측정 완료 결과가 아닙니다.

## 초기 제외 범위

- Bluetooth Sink(휴대폰의 소리를 PC로 수신), HFP/HSP 마이크 구현, LE Audio/LC3
- aptX Adaptive/Lossless, 헤드폰이 지원하지 않는 코덱 강제 사용
- 다중 헤드폰 동시 스트리밍, 게임용 지연 보장, DRM/PAP 보호 콘텐츠 지원 보장
- 모든 Windows 버전·어댑터·OEM Bluetooth 스택 호환
- 결제·계정·라이선스 서버, 자동 업데이트, 상용 서명·판매용 설치 프로그램

## 아직 필요한 결정

| 항목 | 결정 시점 | 확인할 증거 |
| --- | --- | --- |
| 실제 OS·어댑터·헤드폰 | M1 시작 | 기본 재생, Sink capability, 실기 접근 가능 여부 |
| 기본 BthA2dp와 장치별 소유권 전환 | M1 | PnP binding·L2CAP channel·원래 드라이버 복구 실험 |
| ACX 또는 PortCls/WaveRT | M1 | endpoint 생성, PCM 획득, target WDK와 Rust FFI 빌드 |
| 서비스 계정과 driver ACL | M1/M2 | 필요한 접근 권한만으로 실행 가능한지 |
| UI 프레임워크 | M3 | 확정된 화면·상태 계약을 기준으로 native window·접근성·DPI·트레이·Rust IPC 검증 |
| 프로젝트 라이선스·판매 범위 | 외부 코드 반입/릴리스 전 | 권리자 선택, codec 조건·고지·소스 제공 경로 |
